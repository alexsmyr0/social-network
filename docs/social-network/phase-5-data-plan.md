## Queries, atomic effects and signals

| Operation | Permission under lock/snapshot | Atomic effects / post-commit signal |
|---|---|---|
| Event create | Current active membership, supplied current membership ID, visible group | Event plus notices to exact current active members except creator; no response. After commit notification.new to recipients, social.invalidate to current members. |
| Event list/detail/responses | Current membership and event belongs to group | Filter response membership generations before aggregates/paging. No writes/signals. |
| Response | Same plus own response version | Upsert own generation, increment version, commit; social.invalidate to current members, no notice. |
| DM send / upload | Active distinct users, accepted follow either direction; image ownership and recipient binding | Upload stages only; send inserts message/claims pending media, initializes cursors if needed. After commit sender echo, recipient message only if live predicate, requesting ack. No notification row/signal. Exact retry no extra effects/fanout. |
| DM roster/history/media/totals | Participant history or messageable empty pair; committed image requires participation | Only own conversations, filtered active accounts; snapshot counts/preview and page. Media participants still allowed after unfollow. No marks on fetch. |
| DM mark read | Own pair, valid through ID | Monotonic upsert; chat.read to own sessions, notification count unchanged. |
| Group send | Current membership and generation in visible group | Message insert; no notice; group.message to current member sessions and ack to requester after commit. |
| Room summaries/history/totals | Current membership | Current-room records only, including departed authors' retained messages; no writes/signals. |
| Group mark read | Current membership/generation and through ID in same room | Monotonic cursor; chat.read to own current-generation sessions. |
| Admission / departure | Existing B18 authority and stale identity checks | Admission initializes new cursor; departure deletes cursor, leaves events/responses/messages/media. Existing payload-free membership invalidation includes former member; no retroactive event notices. |

Use one shared membership decision rather than copy/pasting role conditions. No follow relationship widens a room/event; no shared group widens a DM/profile. Event notice authorization extends every B12 consumer (list/count/unread/read-one/read-all/excerpt/navigation). Stored hidden notices keep read flags and reappear on readmission. Suppress inactive actors as existing notices do. Inactive contributors' stored events/messages remain with unavailable-account attribution; they cannot read/send or contribute response counts. No account deletion workflow introduced.

Transaction order defines revocation races: send/response first → stored contribution retained, revocation may suppress delivery; revocation first → deny 404 and no contribution/claim/notice. A stale generation after readmission returns STALE_MEMBERSHIP only to a current member. Commit order also defines event notice membership snapshot. Follow loss blocks future sends but not retained participant history/media. Mark-read first then send leaves new message unread; reverse order with old through_id also leaves it unread. Concurrent exact nonce writes yield one 201, one 200 and one fanout. Conflicting nonce writes yield one success, one conflict.

Queued frame authorization must be held through socket write using the existing session admission discipline extended for relationship/membership revocation. A bare query before an unlocked write does not satisfy the contract. Use bounded writes/lock ordering so a slow peer cannot hold the SQLite write transaction indefinitely; B22/B23 document and test their actual coordination. This handoff requires the observable guarantee, adds no new lock framework or service. Reconnect recovery refetches authoritative history and summaries; no offline frame queue.

## Preservation, failure and recovery

Stop old writers and take coordinated SQLite/private `MEDIA_ROOT`/legacy-mount backup before upgrade. Migration 8 copies all notification columns/IDs into new table, adding event_id NULL, and checks row counts and bidirectional EXCEPT over all old columns **before** swap. Preserve sqlite_sequence even when highest ID was deleted. Recreate indexes and existing constraints, foreign_key_check, verify schema; no PRAGMA foreign_keys disabling needed because no table references notices. A new event notice must never match an old content target branch.

Migration 9 uses additive nullable nonce plus new cursors/indexes only; no destructive private_messages rewrite. Compare every old message ID/body/image association/time and media link/object/pending row byte-for-byte before/after. Migrations 8–10 must preserve valid/revoked sessions, earlier read flags, invitation/request identities, posts/drafts/comments/reactions/categories, all group generations and exact avatar/post/comment/DM/pending-image bytes. Do not seed/reset production storage or invoke cleanup that drops referenced media.

Each migration runs through existing transactional runner, verifies foreign keys and safe constraints, and fails startup without readiness on error. Inject failures before copy/ALTER, before swap, before verification and commit; assert no partial schema/data and dirty-version handling according to [migration recovery](backend-migrations.md). Never force-clean automatically. Repeated startup must be no-op with identical mappings/cursors. Test all supported versioned upgrade sources and restore/restart with matching images through B07/A21, beyond native DB-only tests.

Down migrations **refuse** when removing Phase 5 data or cursor state would be lossy; restore coordinated backup with matching runtime instead. A table with even a dedupe nonce or persisted cursor counts as data. No downgrade erases messages/notices silently. B21 owns schema 8 and event preservation tests; B22 owns schema 9, DM media and real-socket matrix; B23 owns schema 10 and membership/fanout/races. Each ticket tests its native/upgrade/failure/restart path; A21 combines real-service two-image evidence. B20 only checks this mapping and fixtures, never claims migration execution.
