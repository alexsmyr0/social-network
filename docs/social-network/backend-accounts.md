# Registration and account API — SN-B04

Versioned social-network databases now use the approved [auth contract](auth-contract.md) for `POST /api/v1/users/register` and authenticated account reads. JSON or multipart text without an avatar creates an account with required email, password, first name, last name and birthdate. Optional nickname and about-me text normalize to SQL `NULL` when blank. Email is lowercased before its case-insensitive uniqueness check; passwords are bcrypt hashed. Each account receives an opaque internal username only for retained forum joins. The Account response derives display name from nickname or names and excludes the password/hash and legacy age, gender and username fields.

Registration validates field lengths, ASCII email shape, real Gregorian date and control characters before insertion. Invalid input returns field codes; duplicate email returns `409 EMAIL_TAKEN`. A valid existing session returns `409 ALREADY_AUTHENTICATED`. Multipart avatar-bearing requests return `503 SERVICE_UNAVAILABLE` before an account is created, as specified until SN-B09 adds media handling. B04 retains the old session creation call; SN-B05 owns cookie lifetime, origin/CSRF checks, independent session behavior and final login/logout/current-user session policy. Legacy forum test fixtures remain on their old schema and handler path; production startup accepts only versioned social-network databases.

Verification on `ticket/sn-b03-b04-account-foundations` (2026-09-27): `go test ./internal/tests -run TestSocial -count=1` and `make test` passed. Tests exercise required and optional fields, account readback, absent secret fields, invalid and future dates, email/password/field errors, case-insensitive duplicate email, non-unique nickname, existing-session rejection, avatar rejection without a partial account, and multipart text registration.
