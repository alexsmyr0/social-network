# Backend session lifecycle — SN-B05

Versioned social-network databases now use independent opaque sessions. Register creates one token; email-only login creates another, revoking only a valid token presented with that login. Session lookup ignores the inherited 12-hour expiry column and accepts an unrevoked token until explicit revocation or account disablement. The browser cookie is host-only, HttpOnly, SameSite=Lax, and renewable for 400 days through successful `/users/me`; HTTPS frontend origins set Secure. Logout is idempotent, revokes only its presented token, clears the cookie after successful revocation, and closes retained sockets for that token before returning 200. Legacy forum fixtures keep their prior single-session behavior.

Versioned API writes require the approved Origin (or Referer fallback only when Origin is absent) and `X-Requested-With: XMLHttpRequest`. The origin comparison uses parsed scheme, host and effective port; WebSocket upgrades require an explicit matching Origin. Auth API responses and errors are JSON with `Cache-Control: no-store`. A database lookup or revocation failure returns 500 without clearing the cookie or claiming logout. Login accepts only the approved email/password JSON object with the 16 KiB body limit, strict keys and valid UTF-8.

WebSocket admission and token revocation share a gate so a concurrent upgrade cannot escape a completed logout. Each retained frame rechecks the token; revocation closes and waits for that token's read pumps while leaving other device sessions connected. New chat features remain outside this ticket.
