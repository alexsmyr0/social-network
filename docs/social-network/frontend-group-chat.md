## Delivered behavior

**Room** (`/groups/:id/chat`, reached from the **Chat** tab of the group navigation) shows the group's name, the newest 30 messages in ascending ID order, "Load earlier messages" for older history, and the shared composer. It is the SN-A19 `MessageList`, `MessageComposer` and `EmojiPicker` unchanged apart from the composer's existing `allowImage` switch: a room has no image control, because the contract neither accepts nor emits room images. Author names are plain text from the server's `sender_username`; nothing links to a profile, a private author exposes only a display name, and an inactive author is the server's "Unavailable account". A message that carries `image_url` is not shown.

**Who sees it.** The room is requested only after the group read confirms the viewer is the creator or a member. An invitee, a pending requester, an outsider and a departed or removed member see the group's name and "Only members of … can chat here." with a link to the group's About page: no room, history, count, composer or room request (`GET /groups/{id}/messages`, `/group-chats`) is made for them. An unknown group is "This group chat isn't available." and a read failure is a retry with nothing shown. The Chat tab itself is offered to members only and, for anyone else, asks the server nothing.

**Sending.** Enter sends (Shift+Enter adds a line). Text is normalized as the contract does (CRLF → LF, trimmed), counted in code points (2,000 emoji are fine, 2,001 are refused), and refused with a message before any request if it has hidden control characters. Each message goes out as `{membership_id, client_id, body}`: the `membership_id` is the one the room was read under and the `client_id` a lowercase v4 nonce reused only to retry that very message. Sends in one room run one after another, so rapid sends are committed and shown in the order they were written; the reply, the socket echo and a refetch merge by ID. A lost or unconfirmed response is retryable with the same nonce and membership (an exact replay returns the original, never a second message); a refused send (membership lost), a conflict, a rejected body and a **stale membership** (a current member holding an old membership ID) are not retryable and offer Discard only. A stale write is never re-sent under the new membership.

**Reading.** The room is marked read only after its messages are rendered on a visible page, with the largest committed ID shown and the membership the room was read under, and only when someone else's message is newer than the known cursor. Fetching, receiving and sending never mark anything read; a hidden tab marks nothing until it is visible. Another tab's read arrives as a `chat.read` frame of kind `group`: it moves the cursor and refetches the totals, and never adds to a count.

**Indicators.** The navigation's message indicator (still a coral square, still never the word "notification") now counts private conversations plus group rooms: `GET /chats/unread` plus `GET /group-chats/unread`. Both are always the server's numbers, message frames refetch them, and the indicator is "—" unless both are known. The **Chat** tab of a group carries that group's own unread count (from `GET /group-chats`, quietly refetched on frames and read changes) and says so in its name ("Chat, 2 unread messages"). The Messages page lists the viewer's group chats under the private conversations (last message, "You:" for the viewer's own, time, unread count, 20 per page, `?rooms=` pages), one room per current membership and nothing for a group the viewer is no longer in. Notices and message counts never move each other.

**Live delivery.** Group frames use the existing single session-owned socket, through the same `subscribe` hook SN-A19 added to the notification state. The message state handles `group.message` (append to the open room by ID, only for the room on screen and only once this account's membership in it has been confirmed) and `chat.read`; it ignores malformed frames and frames for other rooms. A message withheld from a member who has left never reaches the page. A reconnect (and any invalidation) refetches the totals, the room summary and the open room, paging back from the newest message until the last known one is reached, so more than a page of missed messages is recovered once and in order. Sends use `POST /groups/{id}/messages`, not `group.send`: the contract gives both the same command and outcomes and shares the nonce, HTTP returns the committed message, and HTTP sends still fan out to every member session.

## Membership loss and protected state

Every read uses `useSocialResource`. The room keeps its last confirmed data while a refetch runs, so a signal or focus change does not unmount the composer under the person's hands; a failed, missing or denied read, a route change or an account change discards it at once. When the group read says the viewer is no longer a member (or the room read says 404) the messages, the composer, the draft, the attachment state and every pending or failed message are dropped together and the members-only notice replaces them; back navigation shows the same notice, never a cached room. A send in the instant after removal is refused by the server (404): there is no success, no message is appended, and the room clears.

After readmission the room is fresh: the server starts the new membership's cursor at the room's latest message, so the whole history is readable, nothing earlier counts as unread, and the next send goes under the new membership ID. If a membership changes underneath an open room (left and readmitted between two reads, so the old membership ID is stale), the room starts fresh with a short notice that anything unsent was discarded, instead of silently carrying text written under the old membership.

Drafts, pending and failed messages and totals belong to the signed-in account. Logout or an account change discards all of them; a response, send or read that finishes afterwards is dropped by generation and cannot paint, merge or complete into the next account. Room drafts and pending messages live under a `room-<group>` key that can never equal a private conversation's numeric key, so the two never share state.

A deliberate choice: as in SN-A19, a send whose outcome is unknown does not trigger an immediate re-read, because during an outage that read would fail and discard the room, taking the failed message and its Retry with it. The nonce makes a retry safe, and the next focus, reconnect or 60-second read reconciles anything already stored.

## Findings resolved during verification

- A malformed row in a multi-room summary could throw while checking the list's order, before returning the recoverable unavailable state. Invalid rows are now rejected before ordering, with regression checks for invalid rows before and after a valid room.
- The removal/readmission browser journey could go back before the About navigation committed, or admit the member before back navigation had finished mounting the restricted room. It now waits for the About URL and heading before going back, then the chat URL and the visible members-only heading before readmission; absence of messages alone also matched the intervening About page. The first hosted gate on `6166221` passed with this journey retried once ([run](https://github.com/alexsmyr0/social-network/actions/runs/39588511894)); its `about:blank` failure identified the missing forward-navigation wait.
- After both navigation waits, `make test-e2e PLAYWRIGHT_ARGS='a20-group-chat --repeat-each=5 --workers=1'` passes **45/45**, without retries. Biome and the documentation/fixture checks also pass.
- The A19 roster and e2e selectors matched every `.roster-row`, so adding the group-chats list changed their counts; they are now scoped to the "Conversations" list. A15, A16 and A18 compared the exact group tabs and now include Chat.
- The Chat tab's accessible name came out as "Chat , 1 unread message": the flex tab inserts a space between its parts. The name is now set explicitly ("Chat, 1 unread message") and the count is hidden from assistive technology so it is announced once.
- The group navigation overlapped its labels at 360px once a creator saw six tabs (About, Posts, Events, Chat, Members, Join requests); the tabs now size to their labels and wrap.
- A nonmember on a group's About page requested their own room list for the Chat tab's count. The tab now asks nothing unless the role can have a room.
- Under the full-suite coverage run, A19's and A20's 1,235-message recovery tests exceeded the default 5-second limit; both now declare a 30-second limit (the behavior asserted is unchanged).
